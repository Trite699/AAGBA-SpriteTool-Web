AA GBA Sprite Tool

Plays sprite animations stored as a .pix tile sheet (BGR555 palettes + 4bpp 8×8 tiles) and one or more .seq files (each can hold many animations back to back). It also opens a Gyakuten Saiban 3 .gba ROM directly (see “GBA ROM mode” below). Everything runs locally in your browser.

Animation

Frame durations are in 1/60 s ticks. The low byte of the duration field is the time; the high byte holds flags (shown per frame). 254/255 is treated as the end marker (held, or skipped when looping). Animation export uses ffmpeg.wasm (ffmpeg-core.js must be in the ffmpeg/ folder next to this file, the .wasm is fetched from file.garden, and the page must be served over http, not opened as file://).

Tile sheet

Format as decoded here — .pix: a series of banks, each = u32 palette count, N × 16 BGR555 colours (index 0 transparent), then 4bpp 8×8 tiles (low nibble first); if bit 31 of the header word is set the bank is compressed (u32 chunk-offset table, one 16-bit-word RLE chunk per sprite image, and the sprite's tile byte is a chunk index); the 4 bytes after each .seq block's header give the bank's byte offset in the .pix. .seq: a series of animation blocks. Each is u16 0, u16 frame count, 4 more bytes, then 8-byte entries (u16 offset relative to the block start, u16 duration + flags, 4 bytes); each frame is u32 count followed by 4-byte sprites (x s8, y s8, first tile u8, attr u8: bits 7-6 size, 5-4 shape, 3 palette, 2-0 tile index bits 10-8). Sprite tiles are read in NDS-style 1D mapping, origin at the canvas centre. Unknown attribute bits are ignored.

GBA ROM mode — .gba: no .pix/.seq files exist, so the ROM is read directly. Graphics are BIOS-LZ77 blocks. A patch table holds 12-byte entries (pointer to 8bpp tiles, x, y, w, h in tiles); a sequence is a list of 4-byte entries (first patch, count) that draw consecutive patches onto the background. Palettes and base images are not linked to scenes yet, so pick them manually.
